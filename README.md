## Things I've built

- **[`sanity-plugin-singleton-management`](https://github.com/rcmaples/sanity-plugin-singleton-management)** — adopted an abandoned community Sanity plugin that was blocking customers' Studio upgrades on dependency conflicts: refactored it, added tests and CI, republished to npm. It has gone from ~40 weekly downloads at relaunch to 2,400+, with no further marketing. ![weekly downloads](https://img.shields.io/npm/dw/sanity-plugin-singleton-management?style=flat-square&label=downloads%2Fwk&color=CB3837)
- **shftr** ([demo](https://youtu.be/u1l6P-yYj6w)) — workforce management and ticket routing, built first on React/Node/MongoDB and later refactored to Go on Datastore inside FullStory's production stack. Skills-based routing cut median first response on sensitive compliance tickets by 75%. The third generation runs headless, connecting Assembled to Zendesk's Unified Agent Statuses.
- **Support Bridge** — an integration service connecting Slack, an internal customer-record system, and Linear: automated ticket creation, routing, escalation webhooks, and agent assignment for a 14-person support organization, replacing manual triage.
- **Natural-language querying for Sanity** — extended Vision, Sanity's query playground, into natural language → GROQ: MCP server, custom UI, backend services. Prototype to internal demo in days, which got engineering leadership and a cofounder discussing whether to productize it.
- **A marquee EMEA opportunity** — partnered with sales engineering: mapped the prospect's multi-domain customer journey, designed a cross-domain session-stitching approach across three live sites, and wrote the sample code that demonstrated feasibility and guided their implementation.
- **A self-service support portal** — most of the customer-facing portal and the reporting foundation behind it, using AI-assisted prototyping to go from sketch to working software in days rather than weeks.
